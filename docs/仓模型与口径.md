# 服务执行与收费关联仓：模型与口径

本仓只记录可核对的事实、归属与争议，不判定治疗必要性或医疗效果。
来源语义以 `docs/资料口径.md` 为准；本文规定入仓后的表结构、状态机与算法口径。

## 分层

| 层 | 内容 | 可变性 |
| --- | --- | --- |
| 原始层 `raw_*`、`recv_batch`、`recv_file` | 每次接收的文件字节、摘要、批次与原始行 | 只追加，不更新不删除 |
| 决策层 `recv_reconciliation`、`recv_decision` | 人工对账轮次、逐条决策与确认前快照 | 轮次确认后封存 |
| 事实层 `fact_*` | 履约裁决、执行、权益/包归属、退款、现金 | 可由原始层+已确认决策完整重建 |

事实表没有独立于来源的"手工结论"。`rebuild` 每次删除并重算事实表；
同一条业务关系在科室侧与收费处侧下钻到的是同一条 `fact_fulfillment_link`。

## 接收规则

- 同一来源记录键的新文件是整行修订：新批次写入新行，当前行取该键最新批次，历史行保留。
- 文件 SHA-256 已存在时返回 `unchanged`，不增加事实、不新建批次。
- 入仓即校验字段、类型、非负、取值域（state/status/kind）与表间引用；
  引用悬空的文件整体拒绝，不会只入一半。
- 业务时点（来源 ISO 串，含 `+08:00`）与接收时点（批次时刻）分开存储；
  时刻一律以带偏移 ISO 字符串落库，不受数据库会话时区影响。
- `current_rows(table, as_of_seq=n)` 可取任意历史截点的当前行，支持回溯重算。

## 履约裁决（fact_fulfillment_link）

来源声称的每条 `fulfillment_links` 都保留，逐条检查，不按同日同人同价猜测匹配：

1. **引用完整**：execution 与 slot 必须存在，否则 `missing_reference`。
2. **同人**：包的 person 与执行 person 一致，否则 `person_mismatch`。
3. **服务适配**：同类为 `direct`；否则只允许 `substitutions` 中
   `(slot_service, actual_service)` 命中的替代，折算率取 `unit_ratio`
   （每实际单位消耗 `1/unit_ratio` 个原权益单位）；不命中即 `service_mismatch`。
4. **时点**：执行早于包销售时刻记 `execution_before_sale`。
5. **权益容量**：同一 slot 的引用单位累计不得超过 `slots.units`，
   超出的引用记 `slot_capacity_exceeded`。
6. **执行容量**：一次执行被各引用折算消耗的单位累计不得超过 `executions.units`，
   超出记 `execution_capacity_exceeded`。
7. **互斥组**：同一 `exclusive_group` 内一次执行最多兑一项（组可跨包）；
   冲突的全部引用记 `exclusive_conflict:<组>`，不选先录者。

状态：

- `accepted`：无硬规则冲突且执行证据 `confirmed`。
- `pending`：结构无误，但执行证据仍是 `pending`；人工也不能把 pending 强确认为 accepted
  （记 `manual_accept_blocked_pending_evidence`）。
- `disputed`：存在任一硬规则冲突，保留待人工处理，不删执行、不凑平。

申请 `cancelled` 不改变执行事实；补记执行不自动生成收费。

## 合同金额归属

金额以整数分存储，元展示时由分转回。

1. **固定分母**：全包合同价按销售时各 slot 的 `relative_price × units` 权重分摊到 slot，
   分母是全包总权重。只收到部分执行资料时，未分部分留在包内，
   不对已执行项重新归一。
2. **slot 内四类成分**：slot 合同值按单位基数分为
   已核实兑现 / 干净退款 / 争议退款 / 未履行，四类之和恒等于 slot 合同值；
   包级四类之和恒等于合同价。
3. **尾差**：比例分摊先向下取整，剩余每一分分给基数最大项，基数并列按业务键升序。
4. **已核实收入下钻**：slot 的已核实成分再按引用单位分到各 accepted 链接，
   科室执行收入与收费处包收入因此能对上同一条明细。
5. **无法归属备忘** `unresolved_contract_cents_memo`：pending/disputed 引用中
   尚未被已核实或退款占用的单位对应的合同额，仅作提示，不参与四类恒等式，
   避免与争议退款重复计单位。

## 退款与现金

- 退款按 `(at, refund_id)` 次序消耗对应 slot 的可用权益
  （总量减已核实兑现、再减已撤回单位）：可用部分为干净撤回，
  超出部分为触及已履行的争议撤回（`touches_fulfilled_entitlement`），
  服务事实不倒删。
- 每笔退款同时给出**实退金额** `actual_amount_cents` 与按合同折算的**资格额**
  `entitlement_cents`，差异 `difference_cents` 单列，不用实退反推收入。
- `cash` 是真实收退款证据，不因收入归属重新生成，也不与 refunds 相加。
  现金退款按 包/时点/金额 与退款事实匹配：唯一对应为 `matched`，
  多个候选为 `ambiguous`，无候选为 `unmatched`；退款无现金证据记
  `missing_cash_evidence`。

## 人工对账

- `open-round` 重建事实并保存全部事实表快照；轮次 open 期间可逐条 `decide`，
  包括把链接改引到另一 slot（错引套餐纠正）。
- `confirm-round` 封存轮次、令决策生效、重建事实，并返回确认前后逐表逐键的字段级差异；
  改引会体现为明细行 `effective_slot_id` 变化，而不只是汇总数字变化。
  来源 `source_slot_id` 永久保留，可与当前归属对照。
- 已确认轮次不可修改；新一轮可再决策，全部决策历史留痕。
- 人工决策不能凌驾硬规则与证据状态：互斥/容量冲突下的 accepted 不生效，
  pending 证据下的 accepted 不生效。

## 科室与收费处视角

- 科室：`department` / `executions` 按执行日期、团队查服务量与对应合同收入，
  退款不回冲服务次数；pending 与 confirmed 分列。
- 收费处：`packages` / `slots` 按销售包查已兑现、未兑现、干净/争议退款与无法归属备忘。
- 两侧共用 `fact_fulfillment_link` 作为下钻终点；`gaps` 列出
  无已核实兑现的执行（执行侧缺证）与无已核实兑现的收费权益（收费侧缺证）。
